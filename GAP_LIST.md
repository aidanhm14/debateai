### What ships (paths)

- ✅ Server-authoritative clock: Three formats (3/7/15 min) in voice-debate.html; server-side hard cutoff
- ✅ Structured transcript: Per-turn {speaker, start_ms, end_ms, text, audio_url} in `voice_rounds` doc

### Critical files

### Gaps
1. **Incremental transcript save** — ✅ **SHIPPED (2026-07-31)**. Each turn queued + flushed to `voice_rounds/{id}/turns` subcollection every 5s via `/api/log-generation` 'incremental_transcript' action. Survives mid-round network drops.
2. **Latency instrumentation** — ✅ **SHIPPED (2026-07-31)**. GA4 events track `voice_session_start` (session begins), `voice_session_mint_complete` (mint latency), `voice_first_ai_audio` (end-to-end latency). Measures in milliseconds.
3. **Council timeout handling** — 9s hard cap; on timeout all brains silently fail and base system prompt is used. Recommend: expose "council timeout" as a warning metric.
4. **Network resilience** — ✅ **SHIPPED (2026-07-31)**. Local turn buffering + reconnect replay. On connection drop: buffer turns + show '⚠ Connection lost. Attempting to reconnect…'. Wait 6s, retry up to 3× with per-attempt feedback. On reconnect success: '✓ Reconnected. Resuming…' + replay queued turns. GA4 tracks drop duration + attempt count.

### What ships (paths) — PHASE 1 COMPLETE (2026-07-31)
- ✅ Spectate links: `/voice-rfd.html?id={roundId}` serves AI ballot + transcript to anyone with link (unguessable docId = privacy model)
- ✅ Pre-vote questionnaire: Side preference (Gov/Opp/Unsure) + confidence slider (0-100) shown before ballot playback
- ✅ Post-vote questionnaire: Identical questions after full ballot; delta computed server-side (delta_side, delta_confidence)
- ✅ Device identity: Signed cookie `debateos-voter-id` (permanent, 365 days); no signup required
- ✅ Vote persistence: `/api/log-vote` endpoint writes to Firestore with rate limiting + trust_weight anti-gaming
- ❌ Mid-debate prompts: **DEFERRED to WS2 Phase 2**. No real-time polling every 90s (requires live infrastructure).
- ❌ Audience questions: **DEFERRED to WS2 Phase 2**. No Q&A submission + top-Q injection.
- ❌ Reaction rail: **DEFERRED to WS2 Phase 2**. Schema ready but no UI for `{strong point, dodge, citation needed}` taps.
- ✅ Async spectating: Recorded rounds fully supported with pre/post flow.

### What was just shipped (2026-07-31)

**Files changed**: 7 (firestore.rules, voice-rfd.html, log-vote.mjs ×2, vote-collector.js)

**Key components**:
1. **Firestore rules** — added `votes` subcollection to `voice_rounds` with public-write rules (rate limit + validation server-side)
2. **API endpoint** (`/api/log-vote`) — mints device identity, validates side/confidence, persists vote, computes delta vs pre-vote
3. **Client utility** (`vote-collector.js`) — handles device cookie (crypto random ID, 365d), builds pre/post UI forms, attaches listeners
4. **UI integration** (`voice-rfd.html`) — prepends pre-vote card + appends post-vote card with voters attached in real-time

**User flow**:
1. Spectator opens `/voice-rfd?id={roundId}` (no signup)
2. Pre-vote card appears → side (Gov/Opp/Unsure) + confidence (0-100 slider) → submit
3. Ballot/RFD displays
4. Post-vote card appears → same 2 questions → submit
5. Server computes `delta_side` (boolean), `delta_confidence` (int), stores in `votes` doc
6. Vote counts toward eventual aggregates (n=30+) for WS3 analytics

**Anti-gaming**: rate limit 3/min per device, IP clustering detection (server), <5s lag flag (bot indicator), trust_weight starts at 1.0 and decreases for suspicious voters.

### Remaining gaps (Phase 2 + WS3)
1. **Mid-debate prompts** — timer-based injections into live playback (WS2 Phase 2; requires WebSocket/polling infrastructure)
2. **Reaction collection** — UI + real-time sync for timestamped reactions (WS2 Phase 2; requires live layer)
3. **Aggregation dashboard** — `/analytics` page with vote counts, delta curves, etc. (WS3)
4. **Trust weighting in aggregates** — vote aggregates should filter by trust_weight (WS3 query layer)

## Recommended WS1 Hardening Checklist (Before Shipping)

### Latency (p95 < 5s target)
- [ ] Instrument first-ai-word timestamp in GA4
- [ ] Profile WebRTC connect time (goal: <3s)
- [ ] Cache council results per motion/format (avoid re-generating)
- [ ] Consider: SmartCampus fallback if council times out (ship with base prompt, show "faster setup" note)

### Resilience (30s network drop)
- [ ] Implement incremental turn writes to `generations` during round (every 5s or per-turn)
- [ ] On disconnect, resume from last persisted turn (re-open WebRTC + replay user audio buffer)
- [ ] Test: kill network 10s into round → reconnect → verify transcript resumes (no loss)

### Transcript completeness (100-round soak)
- [ ] Test: run 100 rounds to completion, verify zero missing turns
- [ ] Crash injection: forcibly close browser mid-round → recover + verify transcript up to crash point
- [ ] Audio URL validation: all turn audio_urls resolve (no 404s)

### Persona tuning
- [ ] A/B test: compare same motion vs 4 personas (blind user preference)
- [ ] Interrupt timing: should feel natural, not robotic (adjust VAD sensitivity per persona)
- [ ] Aggression calibration: high-aggression personas should interrupt ≥2x more than low

### RFD quality
- [ ] Blind review: 10 rounds scored by the AI, then by human judges (inter-rater reliability ≥ 0.8)
- [ ] Edge cases: one-sided blowout, close decision, withdrawn concessions (check each dimension meaningfully)
